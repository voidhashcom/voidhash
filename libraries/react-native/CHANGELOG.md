# @voidhash/react-native

## 0.3.0

### Minor Changes

- Android: every flow presentation reports exactly one of `$paywall_viewed` (the flow is configured and drawn, with `flow_screen_index` and `flow_screen_name`), `$paywall_load_failed` (with a `reason`) or `$paywall_load_cancelled` (with `cancelledBy`), carrying `loadDurationMs` and, once the flow's package is known, `packageSource` (`network`, `cache` or `bundled`), and a viewed flow then reports `$paywall_completed` (`completion`) or `$paywall_dismissed` (`reason`). The back button closes a flow from its first screen and is reported as `close`. A flow shown again after a configuration change is the same presentation, also when the activity was recreated while the flow was loading: it is then shown above the new activity. `shutdown()` closes the flow on screen and cancels one still loading, so their endings are part of the final flush. Flow events, the flow's own events and its `$screen` events name the flow by `paywallLocationId`, `paywallShowingId`, `paywallId` (instead of `paywall_id`) and `paywallReleaseId`. An A/B test now counts a person when a flow it chose is presented, or handed to the app by `resolvePaywall`, `resolvePaywallState` or React Native's `getPaywallForLocation` (reported as `$paywall_handed_off`), not when its location is preloaded or refreshed. `VoidhashApiClient.resolvePaywallRaw` takes `reportsExposure`; called without it, Voidhash counts the person on resolving. `PaywallCoordinator` and `FlowHost` are no longer public; present flows with `presentFlow`. A location's answer is fresh for 5 minutes instead of an hour, and returning to the foreground or reconnecting refreshes only the locations whose answer is stale, one at a time. A flow package the backend withdrew is deleted from the device and never shown, neither from a cached answer nor as the fallback for a package that cannot be downloaded.
- An app can ship paywalls for a first launch without a connection: put a location's answer (`<location>.json`, with an optional `notAfter` time and `interfaceRevision`) and its build (`<location>.vhfp`) in a `VoidhashFlows` folder of the iOS app bundle or in `assets/voidhash-flows/` on Android. `voidhash location bundle` writes these files. The SDK shows a shipped paywall only when the device has no answer for its location and couldn't reach Voidhash (no connection, a timeout or a server error): never in place of an answer Voidhash gave, never after a rejected key or another error from Voidhash, never when Voidhash answered that the location shows nothing, and never after its `notAfter` or when its SHA-256 or interface revision doesn't match. A build Voidhash withdrew is refused once the device has heard of the withdrawal; on a first launch offline the shipped build is shown however old it is, until its `notAfter`. Purchases from a shipped paywall carry `source: "bundled"` in their paywall context, and every paywall event now carries `packageSource` (`network`, `cache` or `bundled`).
- Flows, their images and their runtime modules download only over HTTPS, and a redirect is followed only to a URL that may be downloaded. A debug build may still use plain `http` for local development: a server on the device itself (`localhost`, `127.0.0.1`, `::1`), and the host of a `baseUrl` set with `http`, such as `http://10.0.2.2:8788` from an Android emulator; a redirect leads to such a server only from another one. A flow whose files are on any other `http` address fails to load as a download failure.

  New API: `FlowUrlPolicy` tells a custom flow renderer which URLs it may download (`permits` and `permitsRedirect` on iOS; `permitted`, `permittedRedirect` and `allowLocalServers` on Android). On iOS, `FlowDownloadError` has a new case, `refusedUrl`, which a `switch` over it must handle.

- Flows show an image uploaded to the project's asset library only when its bytes are the ones recorded when it was uploaded. Each flow build carries the SHA-256 of the uploaded images it shows; the SDKs check downloaded images before showing or caching them and check cached copies each time they are read. An image whose bytes do not match fails to load like any other failed image, is not cached, and is reported once per image and build as a `$paywall_image_integrity_failed` event with the image's address and the flow's ids. Images from other addresses are shown as before, unverified.
- **Apps now show a loading screen while a paywall loads from the network.** When `presentFlow` has to wait for the network, the SDK shows a loading screen 0.4 seconds after the call, at least long enough to be read, until the paywall takes its place; a paywall already on the device appears before then, without it. To turn it off, set `loading` on the renderer to `.none` (iOS, `FlowViewRenderer`) or `FlowLoading.None` (Android, `FlowViewRenderer`), or pass `flowLoading: "none"` to the React Native client. To replace it with your own view, set `.custom { cancel in … }` (iOS) or `FlowLoading.Custom { context, cancel -> … }` (Android).

  The standard loading screen follows light and dark mode, stays inside the safe area and system bars, and screen readers announce it once. The end user can leave it with its close button, the VoiceOver escape gesture, or back on Android. `presentFlow` then returns the outcome `dismissed` with the new `wasShown` set to `false`; a paywall that reached the screen has `wasShown` `true`, so an app can tell leaving the loading screen from closing the paywall (`wasShown` is not part of equality, so results compare as before). Leaving is reported as `$paywall_load_cancelled` with `cancelledBy: "end_user"` once Voidhash's answer named the paywall; a presentation left while its location was still being resolved reports nothing. On Android the loading screen follows the activity through a configuration change.

- Flows can ask for notification or app tracking permission and continue by the answer: allowed, not allowed, or unavailable when the device can't ask. Flows can also read a permission's status without asking, so a screen can be skipped for someone who already answered, and they hear when it changed while the app was in the background.

  - New `flowPermissionHandlers` option (iOS and Android) takes the app's own handler for a permission, keyed by its name (`FlowCapability.notifications.rawValue` on iOS, `FlowCapability.NOTIFICATIONS.wireName` on Android), with the new `FlowPermissionHandler`, `FlowPermissionStatus` and `FlowPermissionResult` types. React Native apps register handlers in native code with `VoidhashFlowPermissionHandlers.register`, as JavaScript can't supply them. A permission is asked only when it is granted in `flowCapabilities`.
  - iOS: the SDK no longer links or references AppTrackingTransparency. An app that wants flows to ask for tracking registers its own handler for it; without one, flows hear that tracking is unavailable. Notifications are still asked by the SDK unless the app registers a handler.
  - Android: the SDK declares no permission. Notifications are asked on Android 13 and later only when the app declares `POST_NOTIFICATIONS`; otherwise flows hear that they are unavailable. Below Android 13 flows learn whether notifications are enabled. Tracking is unavailable on Android.
  - A request made while the same prompt is showing waits for its answer instead of showing a second prompt. A handler that never returns holds up only the flows that asked while it was pending: once they are dismissed, the next flow asks again.

- Flows follow the end user's text size: iOS Dynamic Type, including the larger accessibility sizes, and Android's font size. Large text such as a headline grows less than body text, as each platform grows its own text styles and Android 14 scales fonts. The SDKs report the size to the flow when it appears and again whenever it changes. On iOS the flow lays its texts and text fields out again at the new size in place, keeping its screen, what was typed and how far it was scrolled. On Android a font size change recreates the activity unless it declares `fontScale` in `android:configChanges`; the SDK then shows the same presentation again above the new activity, on the screen the end user was on, with its saved choices and typed values and the keyboard where it was, without its scroll positions or what was typed into a secure field. An activity that declares `fontScale` keeps the flow on screen, and it lays out again in place. A text can keep its designed size or grow only up to a maximum, as set in the editor. A flow follows the text size from the next time it is built and released; a release built before keeps its designed sizes. A code component's text follows the size only when its definition says `followsTextSize`; every component reads it as `$context.fontScale`. New versions of the chips, wheel picker, code input, segmented control and ruler components grow with the text size.

### Patch Changes

- On Android, a link in a flow reaches TalkBack as a link rather than a button, whether it is a pressable part of a text or a whole element: TalkBack says "link" in the reader's language and lists it among the screen's links, and choosing it there or double-tapping it opens it. On Android 6 to 7.1 a link reads as text that can be clicked. Buttons are still announced as buttons.
- Android: flows are drawn with Android's own views by the `ui` module, and depending on it is enough: `presentFlow()` finds the renderer without an option. The modules carry the Maven coordinates `com.voidhash:voidhash`, `com.voidhash:voidhash-core` and `com.voidhash:voidhash-ui`; an included build substitutes them under these names. The flow presentation API is named for flows: the package `com.voidhash.sdk.flows` (was `com.voidhash.sdk.paywall`), `VoidhashOptions.flowRenderer` (was `paywallRenderer`), `FlowRenderer`, `FlowRendererHost`, `FlowRendererSession`, `FlowRendererDiscovery`, `FlowEnvelope`, `FlowRuntimeConfig`, and in `com.voidhash.ui` the `FlowView` and `FlowViewRenderer`. The generated native component bindings import `com.voidhash.ui`.
- Android: `FlowViewRenderer.runtimeMode = RuntimeMode.MODULE` runs each flow on the runtime module its release names, downloaded once, verified and cached, or on the module the SDK bundles when that runs the release; React Native's `flowRuntime: "module"` option turns it on again. `FlowRenderer.useRuntimeModules()` switches a renderer found without naming it.
- Android: a flow shown again after the activity is recreated (a rotation, a font size, locale or dark mode change) comes back where the end user was, instead of at its first screen: on the same screen with the screens before it for the back button, the keyboard on the field that had it, and its saved variables. What it was waiting for goes on: a timer, the app's answer to an app action, a purchase in progress, also one started from a repeated plan card. Nothing it already did runs again: no screen or event is tracked twice, a purchase result is not shown twice, and it is still one view. What the SDK keeps to bring the flow back stays in memory with the presentation and is never written to disk or logged. Scroll positions start at the top, and a later presentation starts at the flow's first screen.
- Flows load an image only from an `https` address on the internet, whether the address was typed in the designer, bound to a value or worked out on the device. An address naming the device itself or its local network (`localhost`, a `.local` name, or a loopback, private, shared, link-local, multicast or reserved IP address, however it is written, including numbers too large to be an address), an address with a user name or password or with whitespace, a backslash or a control character before its path, any other scheme and a relative address are refused, as is a redirect to any of them, and the image shows as failed. The server the app's `baseUrl` names is always allowed over `https`, whatever its address, and so are the images uploaded to the project, so a self-hosted server on a private network keeps working. An embedded `data:` image shows when it is an image of at most 10 MB, base64 or percent-encoded. Debug builds keep loading from the development server they are configured with. The same rule applies to the downloads of flow packages and runtime modules. On iOS, images are decoded at most 4096 pixels on a side, as on Android, and an image declaring more than 8192 × 8192 pixels is not shown.
- A link inside a flow's text now shows it is being pressed: while a finger is down on it, the link draws at half its opacity. A press that starts on a link belongs to the link alone, so a button the text sits in no longer shows its pressed state or activates; lifting the finger away from the link, or scrolling, presses nothing. A finger landing just past a link's last letter, within 6 points, still presses it, the nearer link where two are close. One link is pressed at a time: a second finger on a link meanwhile is ignored, while a second finger on the rest of the text presses the button as it would alone. Pressing a button's text outside its links now presses the button, as pressing the rest of the button does. Links stay separately reachable with VoiceOver and TalkBack.
- A flow opens a link only from the end user's own tap, as it starts a purchase only from one. A link a flow would open as it starts or as a screen appears, after a wait, after the app's answer to an app action or the store's result, as the flow's close attempt, or as a text field gains or loses focus now opens nothing, and the app's log gets a warning. A link opened from a button, a text's link, typing or the return key in a text field, or a logic a tap starts opens as before.
- Flows receive each product's per-period prices, billing period, introductory offer and eligibility, and savings against the flow's other products.

  A layer of a flow that draws nothing and has no interaction, such as a group or a transparent frame, no longer blocks presses: a press on it reaches the button drawn under it. This applies to flows already published, as soon as an app updates the SDK. To keep a layer blocking presses, give it an interaction or a fill that is not fully transparent.

- A flow that goes on after a purchase or restore, such as an onboarding that keeps the end user on screen, now shows its products as the store has them after it: the SDK reads them again from the App Store or Google Play and sends them to the flow before it goes on, so a later screen no longer offers a free trial or introductory price the end user just used, and the screen shown updates in place. A pending purchase reads nothing again: it uses up no offer until it completes. A purchase or restore waits at most two seconds for the store; when the store takes longer, the flow goes on at once and its products update when the store answers. When the store cannot be reached, the flow keeps the products it had. A purchase or restore that ends the flow reads nothing again.

  While a purchase or restore in a flow waits for its result, nothing the platform offers takes a screen away: the back button or gesture does nothing, and a pushed screen cannot be swiped back, nor a sheet or modal dragged down, nor a sheet or dialog closed by a tap beside it. So a flow can no longer go back, show its close attempt (a last-chance offer, for example) to someone who has just paid, or end as dismissed before the result arrives. The flow's own close buttons still close it.

  Android: a flow now reads `introEligible` as false for a subscription for which Google Play returns no introductory offer the end user can have, as after they took a free trial offered to new customers; before, it was unknown. A free trial Play returns to every account without the `voidhash-intro` tag still leaves `introEligible` unknown.

- A text in a flow that shrinks to fit (in a row beside other layers, for example) can now shrink only to the narrowest width its lines can really break at: after a space or a hyphen, between Chinese, Japanese and Korean characters, and never inside a price such as `$59.99 /`, an arrow such as `->` or a word such as `-Yearly`, nor at a no-break space. Before, it could shrink to its widest word between spaces, and a line then broke inside a word or started with a space. In a published flow, such a text can wrap at other places than before, and its layer can be wider or narrower.

  On iOS, justified text in a flow now widens only the spaces between words, as the editor's preview and Android do. Before, iOS also spaced the letters of a line apart and widened no-break spaces, so a justified paragraph can look different than before: letters keep their spacing, and a line without a space between words keeps its natural width.

  On iOS, a link's tap area and a styled run's underline in text with letter spacing now start at the run's first letter; before, they started half the letter spacing early. On Android, an underline under a justified line without spaces now ends where the line ends instead of running to the edge of the box.

- Flows lay out text and read to screen readers more exactly as the editor's preview shows them.

  - Android measures text exactly and without hinting, as the preview does: widths are no longer rounded up to whole pixels, which could wrap or cut a text earlier than the preview; right-to-left and mixed-direction text measures as it is drawn; and the `…` of a cut line is kerned with the letter before it. Glyphs are drawn unhinted too.
  - On iOS and Android, a pressable's accessibility label now joins the texts inside it with line breaks instead of spaces, so screen readers pause between them. An app's own UI tests that match such a label with spaces need updating.
  - On iOS and Android, a button or text field inside another pressable is now reached by VoiceOver and TalkBack on its own, after the pressable, which no longer reads its text.
  - A link that wraps is framed for VoiceOver and TalkBack without the space it wraps at. On iOS, what is under a layer blur can be reached with VoiceOver again.

- A flow's text that fits its line exactly is no longer drawn on two lines. Its box could come out one pixel narrower than the text measured, at some widths and far down long scrolling content, and the last word wrapped.
- A `FLOW_UNSUPPORTED_PACKAGE` error now says which package format the flow's build uses and that this SDK build can't read it, and asks for a report with its `abiVersion`, instead of advising an SDK update. On Android, a device whose CPU the flow renderer's native library doesn't ship for says so.
- iOS: flows are drawn with UIKit's own views by the `VoidhashUI` library, and linking it is enough: `presentFlow()` finds the renderer without an option. The flow presentation API is named for flows: `VoidhashOptions.flowRenderer` (was `paywallRenderer`), `FlowRenderer`, `FlowRendererContext`, `FlowPresenting`, `FlowRendererProviding`, `FlowRendererDiscovery`, `FlowView` and `FlowViewRenderer`. The generated native component bindings import `VoidhashUI`.
- Withdraw a bad paywall build: `voidhash paywall withdraw <paywall> --build <number>` stops it being served anywhere, in production and test and in A/B test variants, after listing what each place shows instead; `voidhash paywall restore` serves it again, also a build older than the recent ones. `voidhash paywall view` marks withdrawn builds, `voidhash location show`, `pin`, `rule` and `voidhash experiment start` warn when a paywall's live build is withdrawn, and `voidhash location show`, `clear` and `archive` say to pause an A/B test running at the location. The Node.js management client adds `paywalls.withdrawBuild`, `paywalls.restoreBuild`, `paywalls.getBuildWithdrawal` and the `isWithdrawn` filter of `paywalls.listBuilds`, and builds carry `isWithdrawn` and `withdrawnAt`. The React Native SDK's generated API types include the optional `withdrawnPackages` of a paywall answer.
- React Native: the package now carries only the React Native layer and installs the native iOS and Android SDKs of the same version from their registries: Swift Package Manager on iOS (through `pod install`, which needs React Native 0.75 or later) and Maven Central on Android. It no longer depends on the `@voidhash/ios` and `@voidhash/android` npm packages, and the Podfile no longer needs `pod "VoidhashCore"` and `pod "Voidhash"` lines: remove them from a bare React Native app, and run `npx expo prebuild --clean` in an Expo app. The config plugin's `renderer` option adds the flow renderer (`VoidhashUI` on iOS, `com.voidhash:voidhash-ui` on Android); in a bare app, set `$VoidhashRenderer = true` in the Podfile's app target and `Voidhash_renderer=true` in `gradle.properties`.

  Android: what the SDK offers SDKs built on it, such as the React Native SDK, is public and marked `@VoidhashHostApi`, which requires an explicit opt-in; apps do not use it.

- The API client's types for resolving a paywall location include the `reportsExposure` request field and the answer's `exposureToken`, and a purchase's paywall context may name its `source`. Nothing the SDK does changes.
- With runtime modules turned on, a flow runs on the runtime module its release names, downloading it when it is not on the device, or meanwhile on the module the SDK bundles when that one runs the release. A module downloaded for another release no longer stands in for it, whatever version it declares.
- A vertical scroll view in a flow lays its content out in the direction set for it in the editor, so a horizontal direction with wrapping shows a grid that scrolls down. Before, its content always stacked in a column. A horizontal scroll view still lines its content up in a row.
- Flow runtime modules are signed. In module mode a downloaded runtime module runs only when its signature verifies under a key built into the SDK; one that does not, or that is older than the runtime built into the SDK, is never stored or run, and the flow shows on the runtime built into the SDK when that can read it. Release builds that carry no signing key keep showing flows on the built-in runtime.

## 0.2.1

### Patch Changes

- In observer mode, `restorePurchases()` on iOS no longer calls `AppStore.sync()`, so you can call it after your other billing SDK's restore without the user being asked to sign in again: it sends what the device already has as a restore. The Restore button of a Voidhash paywall still refreshes the App Store. On React Native, a StoreKit JWS you report is now sent as the purchase's proof instead of being looked up again on the device, and on iOS `reportTransaction(transactionId:)` takes it as `signedTransaction:`.
- Updated dependencies
  - @voidhash/ios@0.2.1
  - @voidhash/android@0.2.1

## 0.2.0

### Minor Changes

- A purchase goes to the person who made it. When another account of your app on the same Apple ID or Google account had the subscription before, the new purchase now moves to the buyer instead of staying with that account. `reportTransaction` reports a purchase unless you pass `isRestore`, and launch scans, renewals and `syncPurchases()` never move a purchase. On iOS, purchases and restores carry the transaction as StoreKit signed it on the device, so a transaction ID alone can no longer move someone's purchase.

### Patch Changes

- Updated dependencies
  - @voidhash/ios@0.2.0
  - @voidhash/android@0.2.0

## 0.1.1

### Patch Changes

- Android builds no longer fail with "defined multiple times" errors, such as for `RNCSafeAreaProviderManagerDelegate`, when the package manager installs copies of other React Native libraries inside the SDK's own `node_modules`. The SDK no longer runs React Native's codegen on Android: its native module is generated by Nitro, so codegen had nothing of its own to build and picked up those copies instead.
- On Android, a pressable part of a flow's text reaches TalkBack as a link rather than a button: TalkBack says "link" in the reader's language and lists it among the screen's links, and choosing it there or double-tapping it presses it.
- Flows tell VoiceOver and TalkBack what each layer is: a layer can carry an accessibility label (translated per language), a role (button, link, header or image), or be hidden from screen readers, and each pressable part of a text is reachable on its own. A pushed screen also settles faster when drawn outside the built-in renderer.
- Present flows made for a location: pass the location's inputs, answer the app actions a flow calls, and read back its outputs and the outcome it ended with, including lists. A flow's text inputs take the system keyboard, move focus from field to field on their own, and work with VoiceOver and TalkBack, which also read the layers a flow describes for them. A flow ends as its purchase or restore says, and runs on the runtime its release names. The native iOS and Android SDKs share these changes.
- Updated dependencies
  - @voidhash/android@0.1.1
  - @voidhash/ios@0.1.1
