Hosted paywalls handle purchases and restores for you. Use the APIs on this page when you build
your own purchase screen and need to load products, start a purchase, or restore earlier ones.

## Load products

`useProducts()` returns the store-backed products configured in your project. Prices come already
formatted for the customer's storefront, so you can render them directly.

```tsx
const { data: products, error, isLoading } = voidhash.useProducts();
const monthly = products.get("monthly");
```

`data` is a `Map` keyed by the project's product slugs. `monthly` is `null` when the store does not
return that product. That usually means the product is not available in the current sandbox
account, country, app version, or provider configuration.

Once you have a product, render its store-provided `displayPrice`.

```tsx
if (!monthly) return null;

return <Text>{monthly.displayPrice}</Text>;
```

## Start a purchase

The SDK opens the native store flow and sends the transaction to Voidhash for server validation. On
success it refreshes the current person, so entitlement grants update without extra work.

`purchase()` resolves to a `Result` from the better-result library and never rejects. Cancellation
is an `Ok` outcome, not an error.

```tsx
const { purchase, error, isLoading } = voidhash.usePurchase({
  onSuccess: () => {
    navigation.goBack();
  },
  onError: (purchaseError) => {
    console.warn("Purchase failed", purchaseError);
  },
});

<Button
  disabled={!monthly || isLoading}
  title={isLoading ? "Purchasing…" : `Continue for ${monthly?.displayPrice ?? ""}`}
  onPress={async () => {
    if (!monthly) return;

    const result = await purchase(monthly);
    if (result.isOk() && result.value.status === "cancelled") {
      // The customer dismissed the store sheet. This is expected, not an error.
    }
  }}
/>;
```

The `Ok` outcome carries one of these status values:

| Status      | Meaning                                                                |
| ----------- | ---------------------------------------------------------------------- |
| `completed` | Voidhash validated the purchase and refreshed the person snapshot.     |
| `cancelled` | The customer dismissed the native store sheet.                         |
| `pending`   | The purchase needs external action. Access arrives once it reconciles. |
| `disabled`  | The client was created with `enabled: false`.                          |

The `Err` channel carries a coded [`VoidhashError`](/sdks/react-native/errors). You will typically
see `FAILED_TO_PURCHASE`, or `READ_ONLY_PURCHASE_NOT_ALLOWED` when the SDK runs in observer mode.

<Callout type="warn" title="Grant access from Voidhash state">
  A successful store dialog is not the entitlement check. Unlock the feature only after the
  refreshed person contains an active grant.
</Callout>

## Restore purchases

Give customers a visible restore action. Restore reconciles store transactions with Voidhash and
refreshes the current person. It never creates a second purchase.

```tsx
await voidhash.client.restorePurchases();
```

## Common failure cases

- **Product is missing.** Verify the store product mapping and the current sandbox environment.
- **Purchase already in progress.** Disable repeated taps while a purchase is running.
- **Customer cancels.** Handle the `cancelled` outcome as an expected result, not an app crash.
- **Purchase succeeds but access is absent.** Retry the person fetch, and verify in Studio that the
  product grants the expected perk.
- **Restore finds nothing.** Confirm the device uses the same App Store or Google Play account as
  the original purchase.
