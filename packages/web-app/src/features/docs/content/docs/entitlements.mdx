The current person snapshot contains entitlements, subscription state, and purchase history. Use
**entitlement grants** to decide what the customer can access.

This page covers checks inside the app. Anything a customer could reach by calling your API
directly must also be checked on the server — see
[Check access from your backend](/backend-entitlements).

## Gate a feature

A perk is available when its grant is `active`. Every SDK lets you wrap that check once so screens
stay simple:

<Tabs items={["React Native", "Swift", "Kotlin"]}>

<Tab value="React Native">

Use the built-in `useHasPerk` hook to check whether the current customer holds an active grant for
a perk:

```tsx
const { hasAccess, isLoading } = voidhash.useHasPerk("premium");

if (isLoading) return null;
return hasAccess ? <PremiumContent /> : <UpgradePrompt />;
```

The hook returns:

| Field       | Meaning                                                                              |
| ----------- | ------------------------------------------------------------------------------------ |
| `hasAccess` | `true` when the person holds an active grant for the perk.                            |
| `grant`     | The active grant behind `hasAccess`, or `null`.                                       |
| `isLoading` | `true` until the first snapshot has loaded.                                           |
| `isStale`   | `true` when `hasAccess` was served from cache because a refresh failed.               |
| `error`     | The refresh error, if any.                                                            |
| `refetch`   | Force a refresh.                                                                      |

Outside React, use the imperative counterpart:

```ts
const { hasAccess, isStale } = await voidhash.client.hasPerk("premium");
```

</Tab>

<Tab value="Swift">

```swift
func hasPerk(_ perkId: String) async throws -> Bool {
    let person = try await voidhash.getCurrentPerson()
    return person?.entitlements.grants.contains {
        $0.perkId == perkId && $0.status == "active"
    } ?? false
}
```

</Tab>

<Tab value="Kotlin">

```kotlin
suspend fun hasPerk(perkId: String): Boolean {
    val person = voidhash.getCurrentPerson() ?: return false
    return person.activePerkIds.contains(perkId)
}
```

</Tab>

</Tabs>

<Callout type="info" title="Gate on perks, not subscription status">
  Subscription status cannot tell you which features a product unlocks, and it misses access from
  one-time purchases or manual grants. Active perk grants are the access-control source of truth.
</Callout>

## Offline and failure behavior

A failed refresh (offline, server error) is **not** proof that the customer has no access. Keep
loading and error states separate from the access decision, and choose a fallback appropriate for
the feature — retry, a cached snapshot, or an upsell screen are all better defaults than silently
locking the feature.

<Tabs items={["React Native", "Swift", "Kotlin"]}>

<Tab value="React Native">

Both check APIs fail open with known-good data:

- If a cached snapshot shows an active grant, `hasAccess` stays `true` and `isStale` is set.
- If there is no cached evidence of access, `client.hasPerk` fails with the refresh error instead
  of answering a confident "no"; the hook reports `hasAccess: false` with `error` set.

Choose a fallback appropriate for each feature:

```tsx
const { hasAccess, isStale, error, refetch } = voidhash.useHasPerk("premium");

if (isStale) {
  // Cached access while offline — usually fine to keep serving content.
}
if (!hasAccess && error) {
  return <RetryScreen onRetry={refetch} />;
}
return hasAccess ? <PremiumContent /> : <UpgradePrompt />;
```

To require fresh confirmation — for example before unlocking a consumable — pass
`{ allowStale: false }` to the imperative check:

```ts
const result = await voidhash.client.hasPerk("premium", { allowStale: false });
if (result.isErr()) {
  // Could not confirm access right now.
}
```

</Tab>

<Tab value="Swift">

`getCurrentPerson()` throws on failure instead of answering a confident "no". Treat a thrown error
as "unknown" and retry or serve your last known state:

```swift
do {
    let hasAccess = try await hasPerk("premium")
    // Route to premium content or the upgrade prompt based on hasAccess.
} catch {
    // Unknown — retry or fall back to cached state, never lock by default.
}
```

</Tab>

<Tab value="Kotlin">

`getCurrentPerson()` throws on failure instead of answering a confident "no". Treat a thrown error
as "unknown" and retry or serve your last known state:

```kotlin
try {
    val hasAccess = hasPerk("premium")
    // Route to premium content or the upgrade prompt based on hasAccess.
} catch (error: VoidhashException) {
    // Unknown — retry or fall back to cached state, never lock by default.
}
```

</Tab>

</Tabs>

## Read the current person

When you need more than a single perk check, read the full snapshot:

<Tabs items={["React Native", "Swift", "Kotlin"]}>

<Tab value="React Native">

```tsx
const { data: person, error, isLoading, refetch } = voidhash.useCurrentPerson();
```

`data` is the person snapshot, or `null` until the first snapshot loads or while the client is
disabled. See [the SDK reference](/sdks/react-native#usecurrentperson) for the full shape.

For advanced cases you can still filter grants directly — prefer `useHasPerk` for gating:

```tsx
const premiumGrant = person?.entitlements.grants.find(
  (grant) => grant.perkId === "premium" && grant.status === "active",
);
```

</Tab>

<Tab value="Swift">

```swift
let person = try await voidhash.getCurrentPerson()
```

Returns `nil` when no person exists yet for this identity.

</Tab>

<Tab value="Kotlin">

```kotlin
val person = voidhash.getCurrentPerson()
```

Returns `null` when no person exists yet for this identity.

</Tab>

</Tabs>

## Grant fields

| Field       | Meaning                                                      |
| ----------- | ------------------------------------------------------------ |
| `perkId`    | The perk slug configured in Studio.                          |
| `status`    | `active` or `expired`.                                       |
| `source`    | `subscription`, `purchase`, or `manual`.                     |
| `sourceId`  | The subscription, purchase, or manual grant that created it. |
| `expiresAt` | Expiration time, or `null` for access without an expiry.     |

Use `subscriptions.current` for account UI such as the current plan or renewal state. Use
`purchases.history` when you need to show past transactions.

## Refresh behavior

The SDK refreshes the person after purchases, restores, and identity changes. Reads use a
stale-while-revalidate cache: a snapshot younger than five minutes is served immediately while a
fresh copy is fetched in the background; older snapshots trigger a network fetch first. To force
a network round-trip:

<Tabs items={["React Native", "Swift", "Kotlin"]}>
<Tab value="React Native">

```ts
await voidhash.client.getCurrentPerson({ forceFetch: true });
// Or re-run the hook's request:
refetch();
```

</Tab>
<Tab value="Swift">

```swift
try await voidhash.getCurrentPerson(forceFetch: true)
```

</Tab>
<Tab value="Kotlin">

```kotlin
voidhash.getCurrentPerson(forceFetch = true)
```

</Tab>
</Tabs>
