---
title: Authentication
description: Choose the correct credential for server, tool, or device requests.
---

Voidhash has three programmatic credential types. Use the narrowest one that fits the caller.

| Credential         | Header                                | Use                                                       |
| ------------------ | ------------------------------------- | --------------------------------------------------------- |
| User API key       | `x-api-key`                           | CLI and tools acting as a signed-in user across projects. |
| Project secret key | `x-secret-key`                        | Server-to-server requests for one project.                |
| Publishable key    | `x-publishable-key` + `x-distinct-id` | Official SDKs and distributed clients.                    |

## Project secret keys

Use a secret key from your backend:

```bash
curl https://api.voidhash.com/api/v1/persons \
  -H "x-secret-key: $VOIDHASH_SECRET_KEY"
```

<Callout type="warn" title="Never expose a secret key">
  A project secret key grants broad access to the project. Do not put it in a mobile app, web
  bundle, public repository, or analytics event. Rotate it immediately after exposure.
</Callout>

## User API keys

User keys are useful for local tools and automation that must access more than one project:

```bash
curl https://api.voidhash.com/api/v1/auth/session \
  -H "x-api-key: $VOIDHASH_API_KEY"
```

The CLI obtains and stores this credential through `voidhash-cli auth login`.

## Publishable keys

Publishable keys are safe to distribute, but they only authorize the device-facing SDK surface and
must be paired with a customer identity:

```bash
curl https://api.voidhash.com/api/v1/sdk/person \
  -H "x-publishable-key: vh_pk_..." \
  -H "x-distinct-id: user_123"
```

Official SDKs also send platform and client metadata required by these endpoints. Prefer the SDK
over calling them directly.

## Verify a credential

Call `GET /api/v1/auth/session`. The response shows how the key was resolved and which project it
can access. A valid key can still receive `403` when it lacks permission for an operation.

## Event capture

`/i/v1/capture` and `/i/v1/batch` use a publishable `token` in the JSON body instead of these
headers. See [Event Capture](/api/event-capture).
