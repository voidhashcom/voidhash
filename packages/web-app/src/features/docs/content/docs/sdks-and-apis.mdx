Voidhash ships three developer surfaces, each with its own documentation tree. Pick the one that matches what you are building — they are designed to be read independently, and each starts with its own overview page.

## React Native SDK

The [React Native SDK](/react-native/overview) is how your app talks to Voidhash: fetching products, displaying paywalls, making purchases, checking subscription status, and identifying users. If you are building the app itself, start here — the [installation guide](/react-native/installation) and [quickstart](/react-native/quickstart) take you from an empty project to a working purchase flow.

## CLI

The [CLI](/cli/overview) is the tool you run on your machine and in CI. It handles [project setup](/cli/init), [type generation](/cli/types) from your schema so product and perk identifiers are checked at compile time, and [paywall deploys](/cli/deploy). If you are configuring a project, wiring up CI, or pushing schema and paywall changes, this is your tree.

## HTTP API

The [HTTP API](/api/overview) is for everything that runs outside the app: server-side subscription checks, webhooks, event capture, and automation against your organization's data. If you are integrating from a backend, syncing entitlements into your own systems, or scripting against Voidhash, start with the [authentication page](/api/authentication) and go from there.

<Callout type="info" title="Not sure where to start?">
  Most projects touch all three: the CLI sets up the project and generates types, the React Native
  SDK powers the app, and the HTTP API backs your server. If this is your first time with Voidhash,
  follow the [installation guide](/react-native/installation) first — it introduces the CLI and SDK
  in the order you will actually use them.
</Callout>
